## Master Ingestion Package + Platform Architecture + Agent Skills + Speech Integration

**Document Purpose:** This is the complete, production-ready specification for a coding agent to build a multi-course language learning platform where Kom (Itanjikom) is the first course. It includes: (1) corrections, (2) ingestion format, (3) platform architecture, (4) Kom course specification, (5) the knowledge-expansion protocol the agent must learn, (6) speech-to-speech integration blueprint, and (7) expanded synthesis.

# PART 0: CORRECTIONS TO PREVIOUS DATA

## 0.1 Corrected Number Entries

The following two entries were malformed or incorrect in the previous JSON draft. Corrected versions:

```json
{"number": 500, "kom": "ighi i täyn", "ipa": "/ìɣì ì tæjn/", "literal": "hundreds of five", "source": "GS", "moderation_status": "verified"}
{"number": 900, "kom": "ighi i bulamö'", "ipa": "/ìɣì ì bulamɔʔ/", "literal": "hundreds of nine", "source": "GS", "moderation_status": "verified"}
```

**Explanation of the correction:**
- `500` was incorrectly written as `"tayn"` without the diaeresis. The correct orthography is **`täyn`** (with umlaut on `a`), as attested throughout `[GS]` Chart 12 and `[TONE]` §4.2.
- `900` was truncated mid-entry. The correct form follows the pattern `ighi i [number]` established for 200 (`ighi i bö`), 300 (`ighi i tal`), and 400 (`ighi i kä`). The nine-form is `bulamö'`, giving `ighi i bulamö'`.

**Full corrected hundreds paradigm:**

```json
{
  "hundreds": [
    {"number": 100, "kom": "ivi", "source": "GS", "moderation_status": "verified"},
```

## 2.2 Technology Stack (Recommended)

| Layer | Technology | Rationale |
|---|---|---|
| **Frontend** | Next.js 14 + TypeScript | SSR, mobile-first, offline PWA |
| **State** | Zustand + React Query | Simple, offline-capable |
| **Backend** | FastAPI (Python) | Async, ML-friendly |
| **Database** | PostgreSQL + pgvector | Relational + vector for semantic search |
| **Cache** | Redis | Session + audio URL caching |
| **Object Storage** | S3-compatible (MinIO) | Audio files |
| **ML Serving** | ONNX Runtime / vLLM | Speech + LLM inference |
| **TTS** | Custom Kom TTS (user-supplied) | Letter/syllable/word audio |
| **ASR** | Fine-tuned Whisper | Speech recognition |
| **S2S** | Modular: ASR + LLM + TTS | Easy to swap components |
| **Deployment** | Docker + Kubernetes | Portable, scalable |

## 2.3 Course Manager Module

The platform must support **multiple courses**, with Kom as the first. Each course is a self-contained module that registers itself with the Course Manager.

```json
{
  "course_registry": {
    "version": "1.0",
    "courses": [
      {
        "course_id": "kom_101",
        "language": "Kom (Itanjikom)",
        "iso_code": "bkm",
        "display_name": "Kom Language Foundations",
        "level": "beginner",
        "total_stages": 16,
        "total_lessons": 120,
        "estimated_hours": 40,
        "prerequisites": [],
        "data_source": "/kom_training_corpus/",
        "audio_source": "/kom_training_corpus/11_audio/",
        "assessment_engine": "standard",
        "speech_engine": "modular_s2s",
        "status": "active"
      }
    ],
    "future_courses": [
      {"language": "Bassa", "iso_code": "bas", "status": "planned"},
      {"language": "Ghomala'", "iso_code": "bbj", "status": "planned"},
      {"language": "Duala", "iso_code": "dua", "status": "planned"}
    ]
  }
}
```

**Design principle:** Adding a new language means adding a new `course_registry` entry and a new corpus directory. No code changes required.

## 2.4 Knowledge Base Module

The Knowledge Base (KB) is a structured, queryable store of all Kom linguistic data. It is the single source of truth for the Lesson Engine and the Expansion Agent.

```json
{

    "collections": {
```

# PART 4: THE KNOWLEDGE EXPANSION PROTOCOL

## 4.1 Overview — Teaching the Agent to Grow the Knowledge Base

The coding agent must be taught how to **safely and accurately expand** the Kom knowledge base using patterns in the existing data. This is a **supervised learning task** — the agent proposes, a human moderator disposes.

**Golden Rule:** The agent may **propose** new knowledge, but it may **never** commit new knowledge to the training corpus without human moderation. All proposals go into `10_synthesis/pending_moderation.jsonl`.

## 4.2 The Five Expansion Types

The agent is authorized to propose five types of expansion:

### Type 1: Phonological Rule Inference
**What:** Propose a rule that predicts how a phoneme behaves in a new context.
**Basis:** Two or more attested examples in the corpus.
**Example:**
```json
{
  "id": "synth_phon_001",
  "type": "phonological_rule",
  "content": "The phoneme /f/ becomes [b] before a voiced stop and [p] before a voiceless stop.",
  "basis": [
    "PHON §6.3: /cof/ → [cɔp.ti] 'sharpen a bit'",
    "PHON §6.3: /bif/ → [bip.ti] 'ask many'",
    "PHON §6.3: /kaf/ → [kap.ti] 'scratch a bit'",
    "PHON §6.3: /dief/ → [dieb.li] 'long (plural)'"
  ],
  "confidence": "high",
  "moderation_status": "pending",
  "synthesized_by": "agent_v1",
  "synthesized_date": "2026-09-15"
}
```

### Type 2: Morphological Pattern Inference
**What:** Propose a pattern for how a morpheme combines with others.
**Basis:** Two or more attested paradigms in the corpus.
**Example:**
```json
{
  "id": "synth_morph_001",
  "type": "morphological_pattern",
  "content": "The suffix -si forms causative verbs from intransitive roots. Pattern: root + -si = causative.",
  "basis": [
    "GS §3.2: ko' 'go up' → ko'si 'make go up'",
    "GS §4.2.1: fi 'come out' → fisi 'bring out'",
    "GS §3.2: kaf 'scratch' → kafsi (causative)"
  ],
  "confidence": "high",
  "moderation_status": "pending",
  "synthesized_by": "agent_v1",
  "synthesized_date": "2026-09-15"
}
```

### Type 3: Lexical Gap Proposal
**What:** Propose a Kom term for a concept not yet in the lexicon, using attested roots + attested derivational patterns.
**Basis:** The proposed term must be composed entirely of attested morphemes.
**Example:**
```json

  "content": "Proposed Kom term for 'school': ndo nwa'li (lit. 'house of book')",

  "moderation_status": "pending",
  "synthesized_by": "agent_v1",
  "synthesized_date": "2026-09-15"

```

**What:** Propose a rule for how sentences are constructed, based on attested examples.
**Basis:** Three or more attested sentences with the same structure.

## 4.3 The Expansion Algorithm — Step by Step

The agent must execute the following algorithm every time it proposes new knowledge.

```
ALGORITHM: safe_knowledge_expansion
INPUT: existing_knowledge_base, expansion_trigger
OUTPUT: pending_moderation_entry

STEP 1: IDENTIFY GAP
  - Scan the knowledge base for missing entries
  - Trigger types: (a) user query with no answer, (b) pattern with < 3 examples, (c) lexicon gap in reader text

STEP 2: GATHER EVIDENCE
  - For each candidate expansion, collect all attested examples
  - Minimum evidence: 2 attested examples for phonology/morphology, 3 for grammar, 2 for lexicon/culture

STEP 3: FORMULATE HYPOTHESIS
  - State the proposed rule/term in clear, falsifiable language
  - Use the exact templates in §4.2

STEP 4: CHECK FOR CONFLICTS
  - Cross-reference against existing knowledge base
  - If contradiction found: set moderation_status = "conflict", flag for human review
  - If no contradiction: proceed

STEP 5: ASSIGN CONFIDENCE
  - high: 3+ attested examples, no exceptions found
  - medium: 2 attested examples, or 3+ with exceptions
  - low: 1 attested example, or extrapolation from a pattern with known exceptions

STEP 6: WRITE PENDING ENTRY
  - Append to 10_synthesis/pending_moderation.jsonl
  - Set moderation_status = "pending"
  - Include all required fields (see schema in §1.3)

STEP 7: NOTIFY MODERATOR
  - Log the entry to a moderation queue
  - The platform MUST display pending entries in an admin dashboard

STEP 8: STOP
  - DO NOT commit to the training corpus
  - DO NOT use in lesson generation
  - WAIT for human moderation
```

# PART 6: SPEECH-TO-SPEECH INTEGRATION BLUEPRINT

## 6.1 Design Principle — Modular, Swappable, Multilingual

The Speech Engine is built as a **pipeline of independent modules**. Each module can be replaced without affecting the others. This makes adding new languages (and swapping in better TTS/ASR) seamless.

## 6.2 Pipeline Architecture

```
USER SPEAKS
    ↓
┌─────────────────┐
│  VAD (Silero)   │  ← Voice Activity Detection
└────────┬────────┘
         ↓
┌─────────────────┐
│  ASR (Whisper)  │  ← Fine-tuned on Kom
│  Kom → Text     │
└────────┬────────┘
         ↓
┌─────────────────┐
│  LLM (Kom-LLM)  │  ← Trained on Kom corpus
│  Text → Text    │
└────────┬────────┘
         ↓
┌─────────────────┐
│  TTS (Kom-TTS)  │  ← Custom user-supplied engine
│  Text → Speech  │
└────────┬────────┘
         ↓
USER HEARS
```

```python
# Pseudocode for the agent's ingestion routine
def ingest_corpus(corpus_path):
    manifest = load_json(f"{corpus_path}/manifest.json")
    for file_entry in manifest["file_index"]:
        path = f"{corpus_path}/{file_entry}"
        if path.endswith(".json"):
            data = load_json(path)
            validate_schema(data, file_entry["schema"])
            insert_into_knowledge_base(data)
        elif path.endswith(".jsonl"):
            for line in load_jsonl(path):
                validate_schema(line, file_entry["schema"])
                insert_into_knowledge_base(line)
    verify_quality_gates(manifest["quality_gates"])
    return "ingestion_complete"
```

## 7.3 Skill 2: Validation

```python
def validate_schema(entry, schema_name):
    required_fields = SCHEMAS[schema_name]["required"]
    for field in required_fields:
        assert field in entry, f"Missing field: {field}"
    assert entry["source"] in VALID_SOURCES
    assert entry["moderation_status"] in ["verified", "pending", "conflict"]
    # Additional checks per schema
    if schema_name == "grapheme":
        assert entry["ipa"].startswith("/") and entry["ipa"].endswith("/")
    if schema_name == "number":
        assert isinstance(entry["number"], int)
    return True
```

## 7.5 Skill 4: Knowledge Expansion

```python
def propose_expansion(gap):
    # Step 1: Identify gap type
    gap_type = classify_gap(gap)
    
    # Step 2: Gather evidence
    evidence = query_knowledge_base_for_evidence(gap_type, gap)
    if len(evidence) < MIN_EVIDENCE[gap_type]:
        return {"status": "insufficient_evidence", "evidence_count": len(evidence)}
    
    # Step 3: Formulate hypothesis
    hypothesis = formulate_hypothesis(gap_type, evidence)
    
    # Step 4: Check for conflicts
    conflicts = check_conflicts(hypothesis)
    if conflicts:
        return {"status": "conflict", "conflicts": conflicts}
    
    # Step 5: Assign confidence
    confidence = assign_confidence(evidence, gap_type)
    
    # Step 6: Write pending entry
    entry = {
        "id": generate_id(),
        "type": gap_type,
        "content": hypothesis,
        "basis": evidence,
        "confidence": confidence,
        "moderation_status": "pending",
        "synthesized_by": "agent_v1",
        "synthesized_date": current_date()
    }
    append_jsonl("10_synthesis/pending_moderation.jsonl", entry)
    
    # Step 7: Notify moderator
    notify_moderator(entry)
    
    # Step 8: Stop
    return {"status": "pending_moderation", "entry_id": entry["id"]}
```

## 7.6 Skill 5: Moderation Integration

```python
def moderation_dashboard():
    pending = load_jsonl("10_synthesis/pending_moderation.jsonl")
    for entry in pending:
        display_entry(entry)
        action = get_moderator_action()
        if action == "approve":
            entry["moderation_status"] = "approved"
            entry["moderator_id"] = get_moderator_id()
            entry["moderation_date"] = current_date()
            append_jsonl("10_synthesis/approved.jsonl", entry)
            add_to_training_corpus(entry)
        elif action == "reject":
            entry["moderation_status"] = "rejected"
            entry["moderation_notes"] = get_moderator_notes()
            append_jsonl("10_synthesis/rejected.jsonl", entry)
        elif action == "needs_revision":
            entry["moderation_status"] = "needs_revision"
            entry["moderation_notes"] = get_moderator_notes()
            send_back_to_agent(entry)
```
